# アーキテクチャ

## 移行方針

固定長表示の拡張にドメイン駆動設計と Clean Architecture を適用する。
アーキテクチャテストは本番ソースを分類し、依存方向、ホスト API、SDK、Node 組み込み、定義 JSON、
依存の組み立てを検査する。デスクトップ版と Web 版では、固定長表示の挙動と組み込み定義を共通にする。

## ソースの構成

| 層                        | 担当                                        |
| ------------------------- | ------------------------------------------- |
| `src/domain`              | 行判定、モード、項目の範囲                  |
| `src/application`         | 形式選択、装飾・検証 DTO、テレメトリポート  |
| `src/infrastructure`      | 組み込み定義、テレメトリ SDK                |
| `src/presentation/vscode` | 形式選択 UI、エディターイベント、装飾、診断 |
| `src/bootstrap`           | 依存の組み立て、有効化、破棄                |
| `src/resource`            | 全銀、JPX、解除用の静的な定義               |

`src/extension.ts` は両ホスト共通の入口。拡張の既存 API を維持し、有効化と破棄を bootstrap に委ねる。

## 文字コードとバイト位置

形式の `length_unit` は `utf16` または `byte` です。省略した場合は従来どおり `utf16` を使い、
`encoding` を省略した形式では現在の文書の文字コードを使います。バイト単位で境界を作る
文字コードは `utf8`、`utf8bom`、`utf16le`、`utf16be`、`shiftjis` に限定します。
バイト長は指定文字コードで現在の文書を再エンコードしたデータ部を基準にし、元ファイルの
バイト列を保持する契約にはしません。

Domain はホスト API を知らず、論理単位の項目範囲と、渡されたバイト境界表から得る
UTF-16 表示位置を扱います。Application の `TextEncodingPort` が行スナップショットの
非同期解析を受け持ちます。Infrastructure の `VscodeTextEncodingAdapter` だけが
`workspace.encode` / `workspace.decode` を呼び、全量往復を照合します。
`encodedBoundaries.ts` は生成 BOM と補助 sentinel をデータ幅から除き、標準 `TextDecoder` の
fatal streaming decode から実在する文字境界を作ります。途中の byte と UTF-16 surrogate
境界は表示可能な範囲へ誤って対応させません。

Presentation では `FileTypeSelection` が quick pick と同じ URI の再読込を管理し、
`DocumentRenderSession` が URI ごとの形式・文書版・encoding・世代・解析状態を所有します。
`EditorDecorations` は editor ごとの装飾ハンドルを保持し、分割表示へ一度の URI 解析結果を
配ります。`diagnostics.ts` は診断 DTO の VS Code 表示と collection の寿命を扱います。
文書の encoding が形式と異なる場合の再読込は VS Code の標準 API を使い、未保存の変更を
上書きしません。古い非同期結果は世代・版・encoding の照合を通過しない限り表示へ適用しません。

## 依存ルール

各層から依存できる先を以下に示す。

- ドメインからドメイン。
- アプリケーションからドメインとアプリケーション。
- インフラストラクチャからドメイン、アプリケーション、インフラストラクチャ、リソース。
- プレゼンテーションからアプリケーションとプレゼンテーション。
- bootstrap からアプリケーション、インフラストラクチャ、プレゼンテーション、bootstrap。
- 拡張の入口から bootstrap。

静的 import、型の import、エクスポート、動的 import、require、import-equals にルールを適用する。
本番ソースはすべて層に分類し、共通コードはブラウザーで動くように保つ。
VS Code API を import できるのは、拡張の入口、bootstrap、インフラストラクチャ、
VS Code 向けプレゼンテーション。テレメトリ SDK はインフラストラクチャ層のアダプターだけが
import する。組み込み定義の読み込みはインフラストラクチャ層に限る。
インフラストラクチャの具体実装はインフラストラクチャ層と bootstrap で生成できる。
アプリケーションのファクトリーを使えるのはアプリケーション層と bootstrap。

参照先は TypeScript の解決規則に従う。静的に解析できない dynamic import や require は違反とする。
相対参照の許可先、VS Code API、SDK、Node 組み込み、JSON の範囲に例外を設けない。
アーキテクチャテスト自身は検査対象外とし、許可例と禁止例でルールの動作を検証する。

依存関係の検査では、列挙したルールに例外を設けない。責務の置き場所や抽象化の妥当性は独立レビューで判断する。

## 設計の責務と境界

重要な判断や抽象化ごとに、担当する層、目的、維持する契約、該当するチェックを、
計画、実装、レビューに記録する。層をまたぐ抽象化、契約やライフサイクルを担う抽象化、
依存方向を変える抽象化は、境界を設ける理由も記録する。
必要な挙動を満たす既存のツールやフレームワークの機能は再利用する。
独自の処理を選ぶ前に、既存の手段で足りない点を特定する。

担当、パッケージ、インターフェース、依存、採用する機能、影響範囲、重要なリスク、検証、
承認の境界を変える場合は Main に戻し、再計画する。

## 互換性とプライバシー

デスクトップ版と Web 版のバンドルの入口と、`engines.vscode` の最小対応版を維持する。
固定長のルールはホストから分離し、アーキテクチャ変更では組み込み定義の内容を保つ。
最低対応版は VS Code 1.100.0。プレゼンテーション層で項目の論理範囲を VS Code の UTF-16 範囲、
スタイル、ホバー表示に変換する。
各文書の解析では先頭行からモードを求める。選択した形式は URI ごとに保持し、表示中の各エディターに
独立した装飾ハンドルを割り当てる。同一 URI の分割表示では一度解析した結果を各表示に適用する。
検証結果はアプリケーション層の DTO から VS Code の `DiagnosticCollection` に変換する。
同一 URI の表示では診断を一度だけ登録し、最後の表示が隠れた時に消去する。再表示で最新内容を再解析する。

テレメトリポートを通して、定義済みのイベントとプロパティだけを送る。
文書のテキスト、ファイル名、パス、認証情報はイベントに含めない。
SDK の生成と接続文字列はインフラストラクチャ層の境界で扱う。
