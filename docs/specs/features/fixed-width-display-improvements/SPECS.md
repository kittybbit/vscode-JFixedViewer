# 固定長表示の改善の仕様

## 目的

固定長データの項目境界を読み取りやすくし、編集やエディターの切替後も、各文書で選んだ形式に沿って
確認できるようにする。境界表示、自動再描画、文書間の干渉防止を一つの機能として扱う。

## 根拠

- 「リポジトリ改善整理」の第6節で選ばれた3件を対象とする。
- [固定長の項目表示](../../../requirements/use-cases/uc-display-fixed-width.md)では、編集後に
  形式を選び直す必要がある。境界の表示方式、色、太さは現在の装飾で固定されている。
- [エディター切替](../../../requirements/use-cases/uc-switch-editors.md)では、形式が同じ文書で
  モードと装飾ハンドルを共有する。別文書の解析結果や再適用が、表示に影響することがある。
- [項目の装飾解除](../../../requirements/use-cases/uc-clear-decorations.md)の選択と、
  選択をキャンセルしたときの動作を継続する。

## 要件と受け入れ条件

1. **境界表示。** 設定で境界線、交互の背景色、区切り記号を選べる。色を指定でき、境界線の太さも
   調整できる。既定の境界線はライトとダークの各テーマで文字と区別できる。
   設定を変更すると、選択済みで対象となる表示に反映される。
2. **編集への追随。** 形式を適用した文書で行を編集、追加、削除すると、編集後の内容から
   区切りとホバーが更新される。ヘッダーの編集や削除でモードが変わった場合は後続行にも反映される。
   元に戻す操作とやり直す操作も対象とする。未選択または解除済みの文書は、編集しても装飾されない。
3. **解析状態の分離。** 解析の開始時にモードを初期化し、同じ文書の1回の解析の中で
   後続行へ引き継ぐ。同じ形式を選んだ2文書を開き、先に一方でモードを設定しても、もう一方の
   ヘッダーなしの行にはそのモードを適用しない。先頭行から同じ内容を解析すると同じ結果になる。
4. **装飾の分離。** 同じ形式を選んだ2文書を並べて表示しても、一方の編集、再適用、解除によって
   もう一方の表示が失われない。切替やセッション内の開き直しで、同じ URI に関連付けた形式の
   表示に戻る。同じ文書の分割表示には、選択、編集、解除の結果をすべての表示に反映する。

## 表示設定

| 設定キー                     | 値                              | 既定値   |
| ---------------------------- | ------------------------------- | -------- |
| `jfixedviewer.boundaryStyle` | `line`、`alternating`、`marker` | `line`   |
| `jfixedviewer.boundaryColor` | 空文字列または `#RRGGBB`        | 空文字列 |
| `jfixedviewer.boundaryWidth` | 1〜4 の整数（ピクセル）         | 1        |

- VS Code のユーザー、ワークスペース、フォルダー設定から対象文書の URI に対応する値を使う。
  不正な値は項目ごとに既定値に戻す。設定画面と設定 JSON から変更できる。
- `line` は実在する項目終端に細い縦線を表示する。`marker` は同じ位置に `│` を表示する。
  縦線と区切り記号は表示上の幅を取ることがある。両方式で、色が空のときはテーマの
  `editor.foreground` を使う。太さの設定は `line` に適用する。
- `alternating` は各行で第2、第4以降の偶数番目の項目に半透明の背景を表示する。
  指定色のアルファ値は `40`（16進）に固定する。色が空のときはテーマの
  `editor.rangeHighlightBackground` を使う。項目の本文色は維持する。
- すべての方式で、ホバーに表示する開始位置、終了位置、幅は定義どおりとする。
  短い行では、文字のある範囲だけに背景とホバーを付ける。定義上の終端が行末を超える項目の
  縦線と記号は表示しない。行末に一致する終端は表示する。

## 決定事項と影響

- [アーキテクチャ](../../architecture.md)に従い、行の照合と項目位置の算出を VS Code から分離する。
  モードは1回の解析内の行間で引き継ぐ。設定、文書の変更通知、装飾の表示は VS Code 側の責務とする。
- 選んだ形式は拡張機能が有効な間、完全な URI に関連付ける。`なし/なし` は関連付けを解除する。
  VS Code の再起動や URI が変わる保存、改名をまたぐ形式の引き継ぎは扱わない。
- 形式選択の対象は選択一覧を閉じた時点のアクティブなテキストエディターとする。
  選択をキャンセルしたときは、表示と関連付けを維持する。
- 表示、切替、解除の恒久ユースケース、アーキテクチャ、README、変更履歴に該当する変更を反映する。

## 互換性

デスクトップ版と Web 版をサポートし、VS Code の最小対応版 `1.75.0` を維持する。
全銀と JPX の組み込み定義、行の照合規則、UTF-16 による位置、日本語のホバー内容、
形式選択のコマンドと選択肢を維持する。装飾は文書内容、保存結果、エディター設定を変更しない。
テレメトリのイベント、形式の値とオプトアウトを維持する。再描画と設定の変更ではイベントを送らない。

## 対象外

- 組み込み形式の追加、利用者定義の読み込み、項目名や型の追加、項目詳細パネル。
- バイト位置と文字コードの変換、標準エディターのフォントの強制、カスタムエディターの追加。
