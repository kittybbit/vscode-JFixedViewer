# ビリングステーション固定長形式対応の仕様

## 目的

NTTドコモビジネスのビリングステーションから取得した展開済みの固定長明細を、
JFixedViewer で選択し、明細を構成する項目と位置を文書の内容を変えずに確認できるようにする。

## 根拠

- [ビリングステーションの公式仕様書・コード表一覧](https://www.ntt.com/business/services/voice-video/discount-statement/billingstation.html#manual)の7系統を調べる。
- [専用線料金内訳書仕様書](https://www.ntt.com/content/dam/nttcom/hq/jp/business/services/voice-video/discount-statement/billingstation/pdf/meisai_senyou.pdf)
  （表紙2025年7月1日、本文1〜3ページ）を専用線料金内訳書の根拠とする。データ部510バイトに
  CRLF が続き、管理 `01`、ヘッダ `11`、データ `12`、エンド `21`、請求単位 `81` で構成する。
- 既存の[ドコモ定義](../../../../src/resource/definitions/docomo.json)はご利用料金管理サービスの
  展開済み `.cla` 7形式を扱う。[NTT東西定義](../../../../src/resource/definitions/ntt.json)は
  2026年9月以降の4形式を扱う。東西の専用線番号別明細内訳書は UTF-8 BOM の700バイト、
  ビリングステーションの専用線料金内訳書は JIS コードと漢字の Shift_JIS を用いる510バイトで、
  ファイル名規則も異なる。
- 現行の利用者向け契約は[固定長の項目表示](../../../requirements/use-cases/uc-display-fixed-width.md)と
  [固定長レコードの検証](../../../requirements/use-cases/uc-validate-fixed-width.md)を参照する。

## 公式資料と採否

公式一覧の「NTTドコモビジネス分」を2026年11月24日に確認した。6個の仕様 ZIP を
展開し、一般の番号別明細内訳書の内部 ZIP 6個も展開した。本文ページは資料内の番号を指す。
旧 Word の表は変換後の XML と本文で照合した。数値は CRLF を除くデータ部のバイト数。
一般7派生、ダイヤル2派生、ビリング、ホスト3派生の各 CSV/TEXT の表紙はいずれも2025年7月。
媒体向けの本文章節が現在のダウンロードに適用される時期は未確認。

MS-DOS の資料にある「JIS」表記から、全派生で `shiftjis` を使えるかは判断できない。
一般の専用線の TEXT §3(3) は一部の漢字欄で JEF DBCS 2バイトと記載し、適用媒体は未確認。
ダイヤル、ビリング、フリーダイヤル等の DOS JIS8 の付録は、符号・数字の値の裏付けに使える。
IBM は EBCDIC や媒体固有の区切りを
扱う契約が必要。保留形式の配布版と適用期間、識別位置、項目単位の照合は未確定。
公式公開資料で裏付けられたときに Main が追加計画を判断する。
[公式操作マニュアル](https://www.billingstation.ntt.com/user/resources/manual/DownloadManual_User.pdf)
本文225ページに、一般の番号別明細と12桁専用線の固定長ダウンロード設定例がある。
画面例は2016年6月で、各派生の現在の配布版や文字コードは確認できない。

VoIP の作成日付と料金月は、和暦と西暦でそれぞれ6桁と4桁を共用する。
2019年5月1日以降の西暦変更は以下の告知と対象一覧の TEXT（2ページ目）による。
対象一覧には通常ダイヤル、ホスト課金、ビリングレポートのダウンロード名も載っている。

### 既存定義との照合

- ドコモ携帯明細の M/F/A/W/J/G/E はすべて Shift_JIS の `.cla`。各幅は順に
  262/138/156/128/126/156/124バイト。データ種類の位置は管理・終端と明細で異なり、
  明細は先頭15または14バイトの後から識別する。
  ビリングステーションとは請求サービス、名前、先頭の項目配置が異なる。
- NTT東西のダイヤル128、電話512、ひかり電話512、専用線700バイトは UTF-8 BOM。
  ファイル名の先頭は順に `M`/`K`/`N`/`S`、後続は契約番号、下線、年月。
  ダイヤルは先頭1バイトの `1`〜`4`、電話・ひかり電話は先頭12バイトの後から、
  専用線は先頭2バイトから識別する。R始まり固定長はその位置が1バイト早く、
  VoIP は電番合計 `5` と終了 `9`、専用線料金は請求単位 `81` を持つ。
  文字コード、名前、レコード構成が一致する既存定義は見つからなかった。
- 既存の形式選択はカテゴリ・形式の表示名を用いる。ファイル名正規表現は既存定義の
  メタデータとして同等に取り扱い、正式名と範囲外の名前をテストする。
- ビリングステーションでのNTT東西データ提供は2026年8月請求分で終了した。
  専用線料金内訳書の会社記号 E/W は以前に展開した資料を表示するために使える。
  [NTT東西データの提供終了のお知らせ](https://www.ntt.com/billing/b/bsmigration2.html)

## 要件と受け入れ条件

- 公式仕様書7系統を展開・確認し、派生形式ごとに、サービス、仕様の版・適用時期、
  固定長かどうか、レコード長・改行、文字コード、ファイル名、レコード識別、項目配置と型、
  参照ページ、採否と根拠を記録する。既存11形式と照合し、判定できない箇所は未確認として残す。
- 公式資料で項目境界と既存形式との差分を確認できた固定長形式を対応候補とする。
  既存定義で同じ仕様を扱える形式は再利用の可否を確認する。
- 採用形式の全レコード種別を正しく判定し、項目名、1始まりのバイト位置、桁数をホバーに表示する。
  ライト・ダークテーマでレコード種別の行色を表示できる。
- 改行バイトを除いた行長、実在する文字境界、既存の数値項目と不明レコードの診断を確認する。
  仕様に固有の数値表記がある場合は、既存の数値項目の契約との対応を計画で示す。
- 解凍済みの公式ファイル名で既存形式と判定が競合しないことを確認する。
  共通のファイル名で複数形式を判別できない場合は、形式選択から指定できることを確認する。
- 採用形式ごとに実バイト数を照合した架空のサンプルを用意し、全レコード種別、日本語の文字境界、
  仕様で定義される継続や例外のうち挙動に影響するものを検証する。
  専用線料金内訳書は通常請求、請求書統合、高額利用割引を照合する。
- デスクトップ版と Web 版で形式を選択して表示・診断でき、既存ドコモ7形式と NTT東西4形式の
  選択、表示、診断が従来どおり動く。利用者向けの形式一覧、サンプル案内、変更履歴を更新する。

## 決定事項と影響

- ビリングステーションは既存のドコモ `.cla` とは別のダウンロードサービスとして扱う。
  新規採用形式は独立した組み込みカテゴリを優先し、表示カテゴリを「NTTドコモビジネス ビリングステーション」、
  カテゴリ識別子を `billingStation` とする。
- 定義 JSON と既存の読み込み、行判定、バイト境界、装飾、ホバー、診断を優先する。
  既存の仕組みで扱えない契約や表記が見つかった場合は、候補の採否を含め Main に判断を戻す。
- 恒久ユースケースへの影響は、採用形式の項目表示とバイト単位の検証の説明。
  終了判定で変更の要否を確認する。

## 互換性

デスクトップ版と Web 版で同じ定義を使い、`package.json` の最低対応 VS Code 1.100.0 を維持する。
既存の形式選択、エディター切替、文書と保存結果、テレメトリのイベントとオプトアウトの契約を維持する。
文書の内容、ファイル名、パス、認証情報はテレメトリに含めない。

## 対象外

- CSV 専用、可変長専用、公開仕様で項目境界を確認できない形式。
- 請求サービスへの接続、ファイルのダウンロード・解凍・結合、料金の再計算、元データの編集。
- 既存ドコモ形式と NTT東西形式の仕様改訂への追随。
