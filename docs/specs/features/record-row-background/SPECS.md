# レコード種別ごとの行背景色の仕様

## 目的

固定長ファイルを標準のテキストエディターで開いたまま、ヘッダー、データ、集計行などを背景色で見分けられるようにする。
ライト、ダーク、ハイコントラストの各テーマで、文字や項目の強調を読み取れるようにする。

## 根拠

- 過去の相談「行背景色変更方法」から Main が確認した要望は、レコード種別ごとの行全体の背景色、
  テーマへの自動追従、ファイル定義 JSON への設定、標準テキストエディターの装飾の利用。
  後続の依頼で、すべての組み込みファイル種別を対象とし、近い役割を持つ行に同じ色を使い、
  `npm run compile` の起動経路も修正することになった。
- [固定長の項目表示](../../../requirements/use-cases/uc-display-fixed-width.md)では、形式の
  `rows` を順に照合し、行の条件とモードが最初に一致した定義で項目を表示する。
  現行の交互色は、行内で偶数番目の項目を見分けるために使う。
- [エディター切替](../../../requirements/use-cases/uc-switch-editors.md)と
  [項目の装飾解除](../../../requirements/use-cases/uc-clear-decorations.md)で定めた
  表示・破棄の単位は、行背景の追加後も適用する。

## 要件と受け入れ条件

- ファイル定義 JSON の `rows` で、行定義ごとに任意で `backgroundColor` を指定できる。
  指定する場合は、ライト系の `light` とダーク系の `dark` にそれぞれ
  `#RRGGBB` または `#RRGGBBAA` の色を指定する。16進数字の大文字・小文字を受け付ける。
  片方が欠けているか、いずれかの値が不正なら、その行の背景色指定を省略した場合と同じように扱う。
  行の条件とモードが最初に一致した定義に背景色があれば、テキスト末尾より右側も含め、
  標準テキストエディターの行全体に適用する。行が短いなど項目装飾が一部または全部描画できない場合も、
  行の判定結果に従って背景色を表示する。
- 背景色は VS Code の現在のテーマに追従する。選択済みの文書を開いたままライト、ダーク、
  ライト系・ダーク系のハイコントラストの各テーマに切り替えたとき、形式の再選択や文書の再読込なしに表示を更新する。
  文字、選択範囲、カーソル位置の項目の強調を読み取れることを確かめる。
- 背景色の指定を省略した行定義を使う行、空行、空白だけの行、どの行定義にも一致しない行には、
  この機能の背景色を適用しない。形式に一致しない行や行長が異なる行の診断は従来どおり表示する。
- 全銀協規定形式、JPX、NTT の全38形式・206行定義に初期色を設定する。近い役割を持つ行には形式をまたいで
  同じ色を使う。ヘッダー・管理は青、通常データは橙、内訳・補足は紫、小計・トレーラは緑、
  エンド・総合計は灰色とする。
  総合振込の各種別の表示は
  [既存のサンプル](../../../../sample/zengin/50200121.sougou_furikomi.dat)で確認できる。
  解除用の「なし/なし」には行定義がなく、表示を解除する。
- 行背景は、各エディターの表示範囲と前後20行に追従し、分割表示では同じ解析結果を使って
  それぞれの表示範囲を描画する。編集後は文書の再解析結果に追従し、行種別やモードの変更、
  行の追加・削除で古い背景色が残らない。形式切替、解除、非表示、再表示、拡張機能の破棄では、
  項目装飾と同じタイミングで行背景を更新、消去または破棄する。
- 行背景を表示した状態で、境界線、区切り記号、ホバー、カーソル位置の強調、診断が引き続き使える。
  `alternating` を選択した場合、行背景の上でも項目ごとの交互色を見分けられる。
  診断を無効にしている場合も、行背景を表示する。
- `npm run compile` でデスクトップ版と Web 版をビルドできる。ビルド単体の実行と Qlty の検証を分け、
  `npm run qlty` とパッケージ作成前の品質検査を維持する。

## 決定事項と影響

- 行背景は既存の行判定とモードの結果に基づく。文書全体の解析結果を URI ごとに共有し、
  スクロール時は各エディターで必要な行だけを描画する。
- VS Code の行全体の装飾と標準の `light`・`dark` オプションを利用する。
  行判定は VS Code の API に依存せず、選んだ行定義の色を項目や診断と同じ解析から得る。
  組み込み定義の行背景には半透明色を使用する。有色行のカーソル位置の項目と交互項目には、
  ハイコントラストでそれぞれの強調を識別できる輪郭を付ける。
  実ホストで文字と既存の強調の見え方を確認する。
- 項目の交互色、カーソル位置の項目の強調、選択範囲と背景色が同じ行に重なること、
  色の付いた形式からの切替で装飾が残ること、
  表示範囲の更新で全文を再走査することが主なリスク。実ホストの重なり方と切替の回帰を確認する。
- 恒久ユースケースの「固定長の項目表示」「エディター切替」「項目の装飾解除」に影響し、
  利用者向け変更履歴への記録が必要になる。「固定長レコードを検証する」の判定条件は維持する。

## 互換性

デスクトップ版と Web 版を対象とし、最小対応版は VS Code 1.100.0 を維持する。
背景色の指定のない既存ファイル定義を引き続き読み込める。文書内容、保存結果、項目幅、文字コード、
既存の表示・診断設定、テレメトリの契約は維持する。

## 対象外

- 外部のファイル定義 JSON の読み込み機能や、行背景色のための新しい VS Code 拡張設定。
- VS Code の既存テーマ色 ID をファイル定義から参照する設定。
- 診断の有無による行背景色の付与。
- 行の判定条件、項目や診断の仕様、固定長形式の内容の変更。
