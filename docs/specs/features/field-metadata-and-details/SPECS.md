# フィールドメタデータと詳細表示の仕様

## 目的

固定長ファイルを読むとき、表示された各項目の名前と位置を確認できるようにする。
対応形式ごとのサンプルで、レコードの構成や項目の見え方を手元で確認できるようにする。

  の最新提案「フィールドメタデータと詳細表示」および全対応形式の仕様照合・サンプル作成の依頼。

## 要件と受け入れ条件

- 項目ごとに名前、長さ、型を定義でき、解析結果から項目番号と開始・終了位置を取得できる。
  幅だけを持つ既存の `columns` 定義も読み込め、従来どおりの境界とホバーを得られる。
- 項目情報のあるレコードのホバーで、行名に加えて項目名、1から数えた開始・終了位置と桁数を確認できる。
  各境界の両側、複数のレコード種別、短い行で、表示位置と定義上の範囲が一致する。
- カーソルがある項目をエディターごとに強調する。カーソル移動、編集による行やモードの変化、
  形式変更、装飾解除、エディター切替や分割表示に追随する。項目がない位置では強調を解除する。
- 組み込みの全銀33形式と JPX 四本値（デリバティブ）1形式を、公式仕様の対応箇所と照合する。
  項目名、型、幅、項目順、レコードの長さと識別条件、モード、該当するファイル名条件を確認する。
  差異は仕様の参照箇所とともに記録し、確認できた定義の誤りを修正する。
- `sample/` に全34形式の架空データを用意する。ファイルを開き、対応する組み込み形式を選び、
  項目の境界と詳細を確認できる。形式の識別に必要な値、レコード順、各項目の長さと埋め方を仕様で確認する。
  レコード種別やモードで表示が変わる形式は、各分岐を確認できる例を用意する。

## 決定事項と影響

- 公式仕様の項目とレコードの条件を、組み込み定義とサンプルを検証する根拠として使う。
  振込入金通知の A/B や預金口座振替の依頼明細・処理結果明細は、個別の組み込み形式として数える。
  装飾解除の `なし/なし` はサンプルの集計対象から除く。
- サンプルは VS Code 上で1行ずつ確認できる形にする。レコード区切りと文字の扱いを説明し、
  固定長の項目には仕様上使える1バイト文字を用いる。改行と固定長のデータ部は区別する。
- 組み込み定義はインフラストラクチャで読み込む。固定長の規則と項目位置はドメインで扱い、
  アプリケーションが項目情報を表示に渡す。ホバーとカーソルの強調は VS Code 向け表示層が扱う。
- 利用者から見える変更は固定長の項目表示、エディター切替、装飾解除のユースケースに照らして検証する。
  恒久文書への反映は計画で該当箇所を特定する。

## 互換性

デスクトップ版、Web 版、最小対応 VS Code 1.75.0 を維持する。VS Code の項目位置は引き続き
UTF-16 座標を使う。既存の組み込み形式の選択、境界の表示設定、旧定義のホバー、文書ごとの解析と
形式選択、エディターごとの装飾、装飾解除を保つ。表示によって文書の内容や保存結果を変えない。
テレメトリのイベント一覧とオプトアウトを維持し、文書の内容、パス、認証情報を送らない。

## 対象外

- 元ファイルのバイト列に基づく表示位置の計算と文字コードの変換。
- ファイルや項目値を利用者のエディター上で診断する機能。
- 新しいファイル形式、外部定義ファイル、サイドバー、専用エディター。
