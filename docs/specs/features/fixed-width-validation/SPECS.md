# 固定長レコード検証の仕様

## 目的

選択した固定長形式と文書を照合し、レコード長、数値項目、未知のレコードの問題を
VS Code の「問題」から確認できるようにする。文書の内容と保存結果は変更しない。

## 根拠

- 参照チャット「リポジトリ改善整理」の最新提案で、次の1機能として推奨された固定長レコード検証。
- ベースは `37d6ab7965266d30526e1590e93ecdf4f544cb20`。
- [固定長の項目表示](../../../requirements/use-cases/uc-display-fixed-width.md)の行判定、
  モード、UTF-16 座標、形式選択を継承する。
- [全銀協 AP-I-13](https://www.zenginkyo.or.jp/fileadmin/res/abstract/efforts/system/jba_protocol_pc.pdf)
  第Ⅱ部 p15 は N を数字、C を数字を含むキャラクターとし、省略する項目の原則値を全 SP としている。
- [サンプルの説明](../../../../sample/README.md)と既存定義を調べた結果、
  省略を許可する数値項目が存在する一方、`fields` に省略可否の情報はない。

## 要件と受け入れ条件

- R1: 選択した形式の行定義とモードに従い、一致したレコードの項目幅の合計と実際の長さを比較する。
  不足と超過の位置、期待長、実際の長さを確認できる。単位は現行と同じ UTF-16 文字位置とし、
  バイト長を保証する表示にしない。
- R2: `type: N` の項目は ASCII 数字のみ、または項目全体が ASCII SP の場合を許容する。
  数字と SP の混在、英字、全角数字などは問題として表示する。
  全 SP の許容は必須項目の検証を省くためで、業務上の正しさを保証するものではない。
- R3: 選択した形式のどの行定義にも一致しないレコードを検出し、行と原因を確認できる。
  既存の表示と同じ行判定・モード遷移を使い、判定規則の相違を作らない。
- R4: 形式選択、文書編集、形式変更に応じて診断を更新する。分割表示でも同じ文書の問題を重複登録しない。
- R5: 設定で検証を無効にでき、無効化時と形式解除時には既存の診断を消す。
  無効の文書と形式未選択の文書では、新しい診断を作らない。
- R6: 文書を閉じた時と拡張の破棄時に診断を適切に除去し、同じ URI の再表示では現在の内容を使う。
- R7: 全銀33形式の既存サンプルおよび JPX サンプルを回帰検証に使い、正常なサンプルを誤検知しない。
- R8: 装飾、ホバー、項目強調、形式解除、エディター切替、テレメトリの既存契約を維持する。
  診断のために文書を書き換えず、内容・パス・認証情報をテレメトリへ送らない。

## 決定事項と影響

- Main は文字種検証を N に限定する判断を行った。C は形式ごとの許可集合を型記号だけでは確定できないため、
  初回の文字種検証対象から外す。未診断を C 型の妥当性確認済みと示さない。型なし、`-`、`columns` のみの項目も文字種は検証せず、行判定と長さは検証する。
- 固定長の規則はドメイン、文書全体の解析と集約はアプリケーション、
  VS Code の診断・設定・イベントはプレゼンテーションに置く。
  表示と検証は同じ `projectFields()` の結果を利用し、文書の走査を共有する。
- 対象は選択済みで表示中の文書とする。最後の表示が隠れたら診断を消し、再表示時に現在の内容を解析する。
  非表示の文書のバックグラウンド検証は行わない。分割表示が1つでも残る URI の診断は維持する。
- `isEmptyOrWhitespace` の行は既存の表示と同様に解析せず、モードを維持する。
  空文書、末尾改行が作る空行、SP・タブ・全角空白だけの行も診断しない。
- 長さ不足では未完了または未到達の N 項目を文字種検証しない。完全に存在する N 項目は検証する。
  長さと別の完全な項目の不正は両方を示す。長さ超過では定義内の完全な項目も検証する。
- 長さ不足の位置は実在する最終文字、超過は期待長から行末、未知行は行全体とする。
  N の不正は該当する項目全体を示す。すべて0始まり・終端を含まない UTF-16 範囲で表す。
  通常の問題は Error とし、コードは `INVALID_LENGTH`、`INVALID_TYPE`、`UNKNOWN_RECORD` とする。
- 診断は文書ごとに先頭から最大1000件。同じ行は長さ、項目番号順の文字種の順で保持する。
  1001件目以降がある場合だけ、文書先頭に Information の `VALIDATION_LIMIT` を1件加え、
  一部を表示している旨と1000件の上限を示す。1000件ちょうどでは打切り表示を出さない。
  上限後も装飾とモード遷移に必要な解析を続ける。無効時は検証処理と診断生成を省く。
- 設定は `jfixedviewer.validationEnabled`（boolean、既定 `true`、resource scope）。
  無効化・再有効化は設定の影響を受ける現在の表示文書に反映する。
  無効化しても項目装飾・ホバーは維持する。編集後は既存と同じ100msのデバウンスで更新する。
- 診断には行・項目名・期待長・実際の長さ・制約の説明だけを使い、実際の項目値を埋め込まない。
  診断に関連した新しいテレメトリイベントは追加しない。
- 診断がないことをファイル全体の完全な妥当性確認と表示しない。
- 恒久ユースケースには診断の表示・更新・解除の挙動、利用者向け文書と変更履歴には新機能と文字位置の制約を反映する。
  更新パスと検証は [計画](TASKS.md)に記録する。

## 互換性

デスクトップ版と Web 版で同じ検証結果を返す。`engines.vscode: ^1.75.0`、既存の形式 ID、
組み込み全銀33形式と JPX、`fields` と従来の `columns` の互換性を維持する。
共通の本番コードをブラウザー対応とし、テレメトリのイベント一覧とオプトアウトを維持する。

## 対象外

- 文字コード変換、バイト位置とバイト長の厳密な検証。
- C 型・型なし・`-` の文字種検証、必須・省略可否、固定値・コード値、レコード順序、件数・合計値の業務検証。
- 新しい形式、外部定義、自動形式判定、フィールド検索や比較。
- データ修正、診断からの自動修正、別件のホバー信頼設定の変更。
