# 表示範囲に応じた装飾の仕様

## 目的

固定長ファイルの全行の装飾を一度に送る処理を改め、大きな文書でも表示中の項目を
表示できるようにする。新しい形式を追加する前に、調査で再現した装飾送信の失敗と
長時間の応答停止を解消する。

## 根拠

Main の[性能確認報告][performance-report]では、ベース
`ee56899fc87d89afdf3e225487ee66111ba37aa5` の全銀10万行で、
`setDecorations` の送信引数の変換中に `RangeError: Invalid string length` が発生した。
JPX1万行では初回処理が約14.6秒、編集後の再処理が約18.2秒だった。
初回処理のうち約10.5秒を装飾の適用が占めた。編集開始から適用完了までは約24.4秒だった。

調査は既存サンプルを一時的に増幅して行った。恒久的な性能検証基盤の追加は要求しない。
今回受け付けるのは、調査結果に基づく表示処理の改善である。

既存の契約は[固定長の項目表示](../../../requirements/use-cases/uc-display-fixed-width.md)、
[エディター切替](../../../requirements/use-cases/uc-switch-editors.md)、
[レコード検証](../../../requirements/use-cases/uc-validate-fixed-width.md)に従う。

## 要件と受け入れ条件

- R1: 装飾の生成と送信は、各エディターの表示範囲と一定の周辺行に限定する。
  表示範囲が同じなら、文書の総行数を増やしても送信する装飾は全行分に増えない。
  各表示範囲の前後20行を文書内へ収め、重複・隣接する行範囲を結合する。
- R2: スクロール後の表示範囲に境界表示とホバーを適用する。`line`、`alternating`、
  `marker`、色、線幅、カーソル位置の項目強調の意味を維持する。
- R3: 同一 URI の分割表示では、一度の文書解析結果を使い、各エディターの異なる
  表示範囲とカーソル位置に応じて装飾する。非表示、再表示、close、形式解除、破棄で
  装飾の寿命と古い処理の失効を維持する。
- R4: モード判定は文書先頭から行い、画面外のヘッダー変更も表示中の行へ反映する。
  検証は表示範囲へ限定せず、全文の診断、1000件上限と案内、URI ごとの寿命を維持する。
- R5: URI、文書版、文字コード、形式、世代を照合し、編集中や形式選択中のスクロールで
  古い解析結果を適用しない。文字コードの安全確認と実在する文字境界の扱いを維持する。
- R6: 既存サンプルを一時増幅した同条件で再測定し、全銀10万行の装飾送信時の例外が
  再発しないことと、全銀・JPX1万行の装飾処理時間・送信量の改善を確認する。
  初回、編集、スクロール、診断、メモリの結果と測定できない項目を記録する。
  時間・送信量の判定と停止条件は [TASKS.md](TASKS.md#性能の再確認) に従う。

## 決定事項と影響

- VS Code の表示範囲とエディターごとの装飾の扱いは Presentation の責務とする。
  固定長の行判定、モード、バイト境界のルールへ VS Code の依存を加えない。
- 全文解析と診断を維持し、表示対象の装飾の生成・送信を分ける。
  URI ごとの解析キャッシュには全文の行別項目索引、行の長さ、設定を保持し、
  全文の `DecorationOptions` を保持しない。各エディターには自身の表示範囲だけの装飾を作る。
- 表示範囲変更では検証や文字コード変換を再実行しない。索引から対象行だけを取り出す。
  解析中の移動は新たな解析を始めず、解析完了時の最新の表示範囲へ適用する。
  同じスナップショット・設定・正規化範囲への重複送信を省く。カーソル強調は別に更新する。
- 全フィールド DTO の保持とバイト境界表のメモリ負荷は残り得る。
  この改善で任意サイズの文書の応答時間や必要メモリを保証しない。
- 恒久ユースケースには、表示範囲への追従と分割表示の受け入れ条件の追記が必要。
  利用者が確認できる改善を `CHANGELOG.md` に記録する。具体的な恒久文書の変更パスと
  アーキテクチャの URI 解析キャッシュとエディター別描画の責務説明も更新する。
  正確な対象パスは TASKS.md に列挙し、計画段階では恒久文書を編集しない。

## 互換性

デスクトップ版と Web 版を維持し、最小対応版 VS Code 1.100.0 を引き上げない。
組み込み全銀・JPXの定義、設定キー、コマンド、表示・検証の意味を維持する。
文書の内容、保存結果、エンコーディングを本機能で書き換えない。
依存方向と依存の組み立ては[アーキテクチャ](../../architecture.md)に従う。
テレメトリのイベントとオプトアウトを維持し、文書内容、パス、診断を送信しない。

## 対象外

- バイト境界変換アルゴリズムの高速化、編集時の差分解析、全文 DTO の保持方法の刷新。
- 新しい固定長形式、自動形式判定、レコード間集計の検証。
- 恒久的なベンチマーク、CI の計測、計測コード、増幅したサンプルの追加。
- 任意サイズの性能保証。JPX10万行は調査でも実測メモリを根拠に未実施である。
