# 固定長レコードを検証する

形式を選んだ文書を検証し、レコードの問題を VS Code の「問題」に表示する。
検証結果は文書の表示だけに使い、内容や保存結果は変更しない。

- 行判定とモードの切替は項目表示と共通にする。空行と空白だけの行は無視する。
- `length_unit` の定義に従って行長を比較する。省略時は従来の `utf16` 文字位置を使い、
  `byte` では形式の文字コードで現在の内容を再エンコードしたデータ部のバイト数を使う。
  短い行は行末、長い行は余分な末尾を示し、改行と生成 BOM は幅に含めない。
- `byte` の項目端が実在する文字境界でない場合は `INVALID_BYTE_BOUNDARY` を表示する。
  その項目は文字の途中を指す装飾や N 型検証を行わず、他の有効な項目と行長検証は続ける。
- 数値型 (`N`) は ASCII 数字、または全て ASCII SP の場合を許容する。数字と SP の混在、
  それ以外の文字は問題にする。短くて項目全体がない場合は長さだけを診断する。
- 文字型 (`C`)、型なし、従来の `columns` だけの項目は、文字種を診断しない。
  空白を許容する数値項目があるため、必須性や業務上の値の妥当性も判定しない。
- 定義のない行を問題にする。診断はファイル内容を引用せず、問題の位置、型、期待値を表示する。
- 一文書あたり問題を最大1000件表示し、超えた場合は一件の案内を追加する。
- `jfixedviewer.validationEnabled`（既定 `true`）で無効にすると、その URI の診断を消す。
  再度有効にすると最新の内容で診断する。形式を解除した時も診断を消す。
- 行長、項目位置、期待幅は形式の単位（桁またはバイト）を表示する。バイト境界の診断も
  1000件上限に含む。検証を無効にしても、安全な表示範囲がない項目は装飾しない。
- 編集をまとめた後に診断を更新する。分割表示では同じ URI の診断を重複させない。
  最後の表示を閉じたり隠したりした場合は診断を消し、再表示で最新の内容を調べる。

文書のテキスト、パス、診断内容をテレメトリへ送らない。
